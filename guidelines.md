# Project Guidelines

These guidelines outline the standards and expectations for anyone participating in the FixFlow AI project. Our goal is to ensure a secure, collaborative, and professional environment.

This repository is publicly accessible to offer developers planning open-source or project contributions an insight into FixFlow AI. 

## Contribution Application Requirement

To participate or contribute to the codebase:
- Interested developers must send an email to **ai.fixflow.helpdesk@gmail.com** before starting any work.
- The email must clearly state why you want to contribute and how you plan to contribute.
- Access, issue assignment, and branch coordination will be handled based on this initial email coordination.

## Code of Conduct

We are committed to providing a welcoming and inclusive environment for everyone. We expect all contributors and participants to:
- Be respectful and professional in all communications.
- Collaborate constructively and help other team members.
- Focus on what is best for the project and the community.
- Provide and accept constructive feedback during reviews.

Unacceptable behaviors include harassment, personal attacks, exclusionary comments, or publishing others' private information without consent.

## Security Policies

Security is critical to the project. Please follow these rules to keep the codebase secure:
- Never commit credentials: Do not include passwords, API keys, private tokens, or other sensitive information in the repository. Use environment variables and add config files to the git ignore list.
- Keep dependencies updated: Regularly check for and update packages that have security vulnerabilities.
- Validate user input: Ensure all data entered by users is validated and sanitized to prevent security issues.
- Report vulnerabilities privately: If you find a security issue, do not create a public issue. Use the private reporting features on GitHub or contact the maintainers directly via email.

## Repository Rules

- Branching: Do not push changes directly to the main or stable branch. All updates must go through a pull request.
- Pull Request Reviews: All pull requests must be reviewed and approved by at least one maintainer before merging.
- Clean Code: Follow standard formatting and structure guidelines for the languages used in this project. Keep functions focused and code well-documented.
