# Contributing to FixFlow AI

Thank you for your interest in contributing to FixFlow AI. This repository is publicly available to offer developers who are planning open-source or project contributions an insight into what FixFlow AI is and how they can contribute.

## How to Get Involved

If you are interested in contributing to this project, you must first send an email to **ai.fixflow.helpdesk@gmail.com**.

In your email, please provide a clear description of:
1. **Why you want to contribute**: Share your motivation and interest in the project.
2. **How you want to contribute**: Describe the specific areas, features, improvements, or fixes you plan to work on.

Please ensure you clearly cover both points. Once the maintainers review and discuss your proposal, they will coordinate with you on the next steps, including issues, branch setup, and code reviews.

## Guidelines for Approved Contributors

Once your contribution plan is approved via email, please follow the guidelines below to submit your changes.

### Reporting Issues

If you find a bug or have a feature suggestion:
- Search existing issues to ensure it has not been reported yet.
- Open a new issue with a descriptive title, steps to reproduce, expected vs. actual behavior, and relevant logs or screenshots.
- For security vulnerabilities, do not open a public issue. Report them privately through the security contact instructions.

### Submitting Pull Requests

1. Fork the repository and create a new branch from the main branch.
2. Keep your changes focused on one specific issue or feature.
3. Write clear commit messages.
4. Ensure that the application runs locally and all tests pass.
5. Submit your pull request to the main branch for review by a maintainer.

## Local Development Setup

1. Fork and clone the repository.
2. Install frontend dependencies in the root folder:
   ```bash
   npm install
   ```
3. Install backend dependencies in the backend folder:
   ```bash
   cd backend
   npm install
   ```
4. Create the required configuration files and environment variables for local testing.
5. Verify your changes locally before submitting.
